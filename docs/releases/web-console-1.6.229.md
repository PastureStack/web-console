## Browser environment workflow

Use `find_resources` to compare every readable same-name environment, select its
opaque reference, and preview `switch_context` or `set_default` with empty
parameters. A human reviews and confirms the named target in the existing modal.
Model apply and the bridge return `needs_user` with a console handoff. The twelve
tool surface and Engine wire-operation enum are unchanged.

Switching waits for the original subscription shutdown, project selection and
schema load. It does not change the personal default. Setting the default awaits
the existing own-user preference save, a fresh readback and target verification;
it does not introduce server-side atomic CAS. These results describe browser
context or account preference, never a verified Engine process.

Reviews retain actor, generation, original Cookie and target identity. Replaced
reviews, late selection/schema tasks and old subscription callbacks cannot
replace a newer context or session. Failure after submission is reported as
unknown when appropriate; it is not automatically retried. Existing authenticated,
NoAuth, ordinary navigation and default fallbacks remain supported.

The UI uses the existing translations in thirteen locales and existing error
components. No raw resource-ID form, new credential storage, role grant, daemon
control or production-site modification is introduced.
